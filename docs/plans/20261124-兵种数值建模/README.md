# 兵种数值建模

## 问题

- 兵种表直接填绝对数值，没有统一尺度回答「一个兵种值多少」「一个阵营整体是否高于另一个」；阵营强弱靠手调开局兵力倍率与援军倍率找平。
- 新文明、新兵种没有可复用的底盘：每个兵种都要从头定数值与行为。

要做到的：先定几种基础单位，所有文明的兵种都在基础单位上调参数、换 3D 模型；每个文明用同样多的点数在各兵种能力上分配，形成特色，同时没有哪个文明的兵种整体高于别的文明。兵种多样性参考帝国时代 2。

## 方案概述

五层：

1. **伤害公式**：全游戏统一成「强度对比式」，重击穿甲、快攻怕甲，但没有打不动的情况。
2. **原型定底盘**：系统只认原型与标签，不认具体兵种。
3. **估值函数算点数**：兵种按等比阶梯调各维度，估值函数把整张面板折成净点数。
4. **阵营预算按比重加权**：点数发到每份兵力上，各阵营加权后相等。
5. **无头对战校准**：估值函数的参数与兵力占用靠实测修正，预算写成测试。

## 关键设计决策

### 伤害公式

- 伤害 = d × d ÷（d + 2 × 护甲 ×（1 − 破甲）），d = 攻击 × 克制倍率（打建筑时乘对建筑倍率）。单位与建筑同一条公式，不设保底。
- 不照搬帝国时代 2 的减法（各攻击类别「攻击 − 护甲」求和、保底 1）。理由：减法会出现打不动的情况，帝国时代 2 靠玩家现造克制兵种来化解；本游戏的阵营编制是固定的，打不动就成了解不开的阵营对阵劣势，而且每点护甲值多少随对手单次伤害剧烈变化，没法定价。
- 不用纯比例减伤（伤害 ×10 ÷（10 + 护甲））。理由：重击和快击变得完全等价，「重击穿甲」这条兵种差异没了，现有护甲数值也要全部重调。
- 强度对比式在常见区间与现在的数值接近（弓 9 打远程护甲 5：现在 4，新公式 4.3），极端处变软（连弩 6 打远程护甲 5：现在保底 1，新公式 2.3），所以现有护甲数值基本沿用；每点护甲的价值随护甲线性增长，可以定价。

### 原型与标签

- 七种原型：近战步兵、远程步兵、近战骑兵、远程骑兵、神职、载具、远程器械。
- 原型定四样：行为（近战或远程、能否边走边打、是否工程、是否治疗）、骨架与动画（各文明只换外观）、基准面板（即「基础单位」，净点数 0）、开放哪些维度及各自的上下限。
- 与现有类别的对应：步兵与枪兵并入近战步兵，远程即远程步兵，骑兵即近战骑兵，骑射即远程骑兵，战象归载具（冲阵巨物，战车、冲车共用），器械即远程器械，神职是新增。
- 标签（借鉴帝国时代 2 的攻击类别 × 护甲类别）：每个兵种带原型标签和特性标签；克制是攻击方对带某个标签的目标的倍率，受击修正是防守方被带某个标签的攻击方打时的倍率（小于 1 是抗性，大于 1 是弱点）；命中的倍率全部相乘。
- 原型之间的固定克制（如骑兵打远程 ×1.4）留在原型上，全阵营一样，不占点数；兵种特有的克制与受击修正是特性，要计点。
- 枪兵不再是类别，「长柄」成为特性：反骑、立枪拒马，同时仍被步兵克（×1.25）、仍让骑兵打它减伤（×0.8）、不吃载具对近战步兵的 ×1.2。理由：现有行为不变，定价时利弊都算进去。

### 点数

- 价值 = 有效生命 × 有效输出 × 机动、射程等修正。理由：人数相同时，有效生命与有效输出的乘积大的一方赢。
- 净点数 = 以 1.05 为底、兵种价值与原型基准价值之比的对数：+14 点约翻倍，净点数相同的兵种价值相同，点数可以直接相加比较。
- 点数由估值函数从整张面板算出，不靠逐项查价目表相加。理由：新伤害公式下护甲、破甲、节奏的价值取决于对手，要对着一支参考军算；生命、输出这类等比维度算出来仍是每级正好 1 点。
- 参考军是「标准混编军」：各原型的基准单位按一张固定的原型比重表混编（初值取现有四阵营的平均），只在校准时更新。它给出参考护甲分布、参考打击强度与各标签的占比。理由：比重固定，调某个阵营的编制才不会牵动所有兵种的点数。
- 攻击不再拆成「攻击」「攻速」两个维度，改成「输出」（每秒伤害，只改间隔）与「节奏」（单次伤害与间隔同乘：重击慢打或轻击快打）。理由：连弩（6 / 0.6 秒）与铁炮（46 / 4.8 秒）每秒伤害几乎相同，差的只是节奏；分开计会出现互相抵消的大数。
- 维度可以降到基准以下换回点数（有下限）。理由：否则做不出「玻璃大炮」和「步兵单薄」。
- 等比维度超过 +6 级后每级多收 1 点，防止堆到极端。
- 等级和高级形态对所有兵种是同一套倍率，不进预算。
- AI 战力估值取价值的平方根（人数等效）。理由：现有估值就是这个量级，士气、AI、经验门槛都按它调过。

### 阵营预算

- 按比重加权：阵营点数 = Σ 兵种净点数 × 该兵种的比重，各阵营相等。理由：点数投在占全军 36% 的主力上和投在占 2% 的器械上，对整军的价值差十几倍；不加权的话「主力加满、冷门扣光」就是总点数相同下的最强解。
- 兵力占用：每个原型一个占用值（步兵 1、骑兵 2……），校准到基准状态下每份兵力等值；开局兵力和援军都按兵力份数计，不再按人头。
- 比重表把援军编成折进去：按标准据点组合估出各兵种的预期援军量，和开局编制按合成比例合成。理由：援军编成与开局编制不同，只按开局编制算会被「高点数兵种集中放进援军」绕过。标准据点组合与合成比例由电脑对电脑的整局统计实测得出。
- 兵员与援军数量纳入同一笔预算，作为阵营级维度花点数买（多兵就少质量）：总兵力 +3.5% 约合平均每份 1 点，兵员与援军各按自己在总兵力里的占比折算。理由：保留「兵多 / 兵精」的阵营特色，又不让它游离在预算之外。
- 预算大小取现有四阵营倒推值的中位数。
- 编制比重由阵营自定；兵种数量与原型覆盖不作统一要求（可以缺某个原型，同一原型可以有多个兵种）。理由：加权后怎么配都公平。
- 单兵种净点数限 −8…+16。理由：点数相等只保证一阶平衡，极端偏科仍略占便宜，靠上下限和循环赛收口。
- 现有兵种先照实倒推成点数、不截断；级数范围与单兵种上下限到调平预算时才执行，届时按倒推出的分布核定范围。理由：调平那一步本来就要动数值，迁移当步不改变兵种强度。

### 校准

- 模拟层能无头运行，参数靠实测：以生命为一般等价物校准各维度，用各原型基准与标准混编军打成平手所需的人数定兵力占用，用电脑对电脑的循环赛验收（任一对阵胜率 40–60%）。
- 预算与上下限写成测试：「没有哪个文明整体更高」由测试保证。

### 数据形态

- 兵种表从填绝对数值改成填「原型、各维度级数、特性」，面板在展开兵种时算出；编制比重仍在阵营定义里。

## 待定

- **建筑的护甲、生命与攻击机制是否整体重做**：伤害公式已经统一，但这三样本身要不要重新设计尚未讨论；对建筑倍率、最近射程这类只影响攻城的属性怎么计点一并待定，迁移时照原值保留、暂不计点。
- **神职的治疗规则，载具里战车与冲车的行为**：尚未设计，对应里程碑未写；原型里神职暂不落地。
- **渲染侧「骨架与动画归原型、各文明只换外观」怎么落**：载具与远程器械下各兵种的骨架并不相同（战象、投石机、弩炮、火箭车、火炮）。本计划的里程碑不动渲染侧的模型与动画。
- **各维度的步长、级数范围与特性价目都是初值**，未经对战校准。
