# 兵种表点数化

> 目标: 兵种表从填绝对数值改为填「原型、各维度级数、特性」，面板由原型基准与阶梯算出；现有 28 个兵种照实倒推成级数；每个兵种有实测点数（测量工具量出，作准）与估算点数（查价目表，指路）。
> 完成判据: 列入维度的属性在兵种表里都只填级数，不计点的字段与特性参数照原值保留；倒推后各兵种每个维度与改动前的偏差不超过半个步长，越出级数范围的不截断、列成清单；兵种实测表由工具生成并提交，兵种定义或规则变了而表没重新生成时测试失败；价目表按本文的规程全部重量过；估算点数与实测点数相差超过 1 点的兵种列成清单；阵营循环赛里各阵营平均优势与改动前相差不超过 0.05。

依赖 [01-对战测量工具.md](01-对战测量工具.md)、[02-伤害公式与经验值.md](02-伤害公式与经验值.md)、[03-兵种类别改为原型.md](03-兵种类别改为原型.md)。

## 技术设计

- [ ] 原型基准面板：每个原型一份，取法同 [01-对战测量工具.md](01-对战测量工具.md) 的基准单位；近战步兵把原来的步兵与枪兵合在一起重新取。载具的基准带践踏，远程骑兵的基准带边走边射，近战骑兵的基准带冲锋，其余特性都不带
- [ ] 标准混编军的位置表随之改为：近战步兵 26、近战步兵（带长柄）22、远程步兵 31、近战骑兵 12、远程骑兵 5、远程器械 3、载具 1。带长柄的位置用「近战步兵基准 + 长柄特性」，长柄取原枪兵类别的缺省参数（对近战骑兵 ×2.4、对远程骑兵 ×2、对载具 ×2，立枪反伤 60）
- [ ] 兵种测量换哪个位置：带长柄的兵种换带长柄的位置，其余近战步兵换不带长柄的位置，其它原型换自己的位置
- [ ] 原型声明开放哪些维度，并可以为维度声明自己的上下限；没声明的取下表。级数都相对原型基准：

  | 维度 | 级数范围（初值） |
  |---|---|
  | 生命、输出 | −6…+12 |
  | 节奏 | −8…+8 |
  | 近战护甲、远程护甲 | −3…+8，且护甲值不低于 0 |
  | 机动、射程 | −4…+6 |
  | 纪律、冲击 | −3…+6 |
  | 治疗（神职落地后启用） | −4…+8 |

  步长见 [01-对战测量工具.md](01-对战测量工具.md)「技术设计」的阶梯表；范围在 [06-阵营点数预算.md](06-阵营点数预算.md) 核定后才执行
- [ ] 兵种定义：原型、各维度级数、特性清单
- [ ] 点数的单位：1 点 = 标准混编军全军生命加 1 级；兵种点数指「标准混编军里它对应的位置整个换成它」值几点
- [ ] 兵种实测表：用兵种测量逐个量出，连同标准误存成数据文件提交；表里记下生成时兵种定义与规则的指纹，供测试判断是否过期
- [ ] 价目表：每个位置、每个开放维度一格，含义是「该位置全员加 1 级值几点」，加级与减级分开记。全部用维度测量按下面的规程重量，不沿用原型里的数字：
  - 生命、输出、纪律、冲击各量加 8 级与减 8 级，节奏、机动、射程量 ±4 级，护甲量 +4 级与 −3 级，每格 = 量出的点数 ÷ 级数
  - 特性各量一次：位置基准带上它与不带它之差，就是它的价目；位置基准本来就带的特性（长柄、冲锋、践踏、边走边射）不另计价
  - 特性参数与位置基准不同的（如长戟兵对骑兵 ×2.5），差异不进估算，由兵种实测体现
  - 结果不显著的格子记 0
- [ ] 机动、射程、纪律的价目取「实测值」与「地板价」中较大的一个，地板价 = 同位置生命价目的三分之一；实测为负也按地板价。理由：它们的价值在整局里，平地量不出，不能让人白拿或靠它换回点数。正式价格在 [07-整局校准.md](07-整局校准.md) 定
- [ ] 其余维度量出来是 0 就记 0（如远程步兵的护甲、近战骑兵的输出）。估算点数因此可以白堆这些维度，这是有意的：阵营预算以实测为准，白堆不会带来实测强度
- [ ] 估算点数 = Σ 价目 × 级数 + 特性价目
- [ ] 战力估值 = 原型基准的战力估值 × 1.05 的（估算点数 ÷（该位置的生命价目 + 输出价目））次方，即把点数折成「生命与输出各加几级」
- [ ] 经验值按原型给：每个原型一个常量，取原型基准的战力估值 × 10；03 留下的「长柄兵种沿用枪兵经验值」到这里取消
- [ ] 等级与高级形态仍是全兵种统一的倍率，不计点

## 实现方案

- [ ] 改动前跑一次阵营循环赛作基线
- [ ] 定六个原型的基准面板，写倒推工具：把现有每个兵种的面板换算成各维度最接近的级数，输出越限清单
- [ ] 兵种表改成级数与特性的写法，面板在展开兵种时由基准与阶梯算出
- [ ] 测量工具的基准单位与位置表改成按原型
- [ ] 重量价目表，生成兵种实测表，加过期检查的测试
- [ ] 替换战力估值与经验值的来源
- [ ] 重跑循环赛，与基线对照

## 开发者提示

- **可复用能力**：内容层「登记后统一展开」的兵种展开流程（现在在这里合并类别缺省值、生成高级形态、按等级展开数值）；测量工具的维度测量与兵种测量。
- **开发要点**：
  - 原型里量过的价目与 28 个兵种的点数见原型验证记录，可以用来核对量级，但不能直接填：那时步兵与枪兵是两个基准，价目表又是按「各位置生命价目合计为 1」归一的，比按标尺斜率折算的小约两成。
  - 现有战力估值是「生命 × 每秒伤害」开平方的量级，士气的敌我战力对比与 AI 的兵力判断都按这个量级调过。
  - 生命有一个全局倍率（控制会战节奏），在展开时乘上，与点数无关。
  - 级数范围与单兵种上下限在本里程碑不执行。
  - 对建筑倍率、最近射程不计点（见 [README.md](README.md)「待定」），迁移时照原值保留。
  - 28 个兵种量一遍约 17 分钟单核时间；价目表约 80 次测量，人少的位置每次要几分钟，总共是几个小时的单核时间，要并行。
  - 数值表以产品文档为准，改完同步。
- **参考文档**：[原型验证记录.md](原型验证记录.md)「各原型的生命与输出值多少」「其它维度」「现有兵种的实测值」、`docs/product/factions.md`「兵种数值」、`docs/product/units.md`「等级与经验」「高级形态」「兵种特性」、`docs/product/morale.md`「士气与溃逃」、`docs/coding-standards.md`
