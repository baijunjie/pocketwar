# 开发笔记

记录从代码和提交历史里读不出来的东西：需求的来龙去脉、试过又放弃的路、踩过的坑、还没验证的事。
玩法、操作、目录结构见 [README](../README.md)，这里不重复。

## 需求与取舍的来历

- **原始需求**：同屏上千单位的即时战略，浏览器运行；四个阵营（中国、日本、罗马、波斯）各有特点；
  不建造不发展，像「突袭」系列那样直接给一整支部队；单机；大地图，有地形、城池、营地，建筑全部可破坏；
  占领资源点后定时从后方来援军。
- **原创作品**：名称「烽烟」。不照搬任何现有游戏的名称、美术、文明设计或具体外观。
- **画面走过的三步**，每一步都是用户看过之后否掉上一步：
  1. 2D 俯视贴图 —— 「怎么是纸片人」，要全 3D。
  2. 3D + CC0 卡通素材包（Kenney Mini Characters / Castle Kit / Survival Kit、KayKit Medieval Hexagon）——
     「不要 Q 版，要写实」。这些包已从仓库移除。
  3. 现状：人物、器械、战象、建筑、树石全部由代码按真人比例建模，只有马用 CC0 模型。
- **为什么不用现成的写实模型**：调研过 Kenney、KayKit、Quaternius、poly.pizza、OpenGameArt，
  没有找到 CC0、带骨骼动画、写实精度的古代士兵；也没有 CC0 的中 / 日 / 罗马 / 波斯风格建筑包，
  没有可直接用的 CC0 带行走动画的大象。Quaternius 的成人比例人物包是候选，但官方 Google Drive 当时限流下不动。
  用户最后说「没有的话你就自己做」。以后如果用户自己提供或购买模型，`rig.ts` 的烘焙流程可以直接接 glTF 骨骼模型
  （马就是这么接的）。
- **写实程度的上限**：现在是低多边形、纯色顶点色、无贴图。离商业 3D 即时战略的精度有差距，用户知情。
- **阵营平衡按用户意思暂停**：「先不用关注平衡，我要先看效果」。用户发话前不要再调数值。
  停手前的数据：36 局 AI 对战胜场为日本 14/18、中国 8/18、波斯 8/18、罗马 6/18；
  那之后还改过一次参数，整局胜率没有重测。平衡工具在测试里：
  `VITE_BALANCE=duel npx vitest run -t 对冲`（平地对冲）、
  `VITE_BALANCE=1 VITE_ROUND0=<轮次> npx vitest run -t 打完整局`（整局）。

## 协作约定

- 下载任何第三方文件（含 npm 包）之前，先向用户说明文件名、来源、授权、大小并得到明确同意。
  只用 CC0 或同等宽松授权的素材，来源记在 README 的「素材」一节。
- 用户用简体中文交流，喜欢简短直接的回答；尽早给能看的版本，而不是全部做完才展示。
- 提交用 Conventional Commits、中文、不留 AI 痕迹；在分支 + `.worktrees/<名字>` 工作树里开发，
  交付前压成一个提交，快进合并到 main。

## 模拟层与渲染层的边界

- `src/sim/` 是纯逻辑，可在 Node 里无头运行，**世界是平的**：丘陵、山只是地形类型。
  高度只存在于渲染层（`terrain.ts` 的高度场），单位脚下高度由 `Renderer.groundY` 现算。
- 坐标对应：模拟的 `(x, y)` → three.js 的 `(x, z)`，`y` 轴朝上。单位是世界像素，每格 32，士兵按每米 10 像素建模。
- 为 3D 在模拟层只加了一样东西：`World.dir`（朝向角，`atan2(dy, dx)`，每秒最多转 9 弧度）和尸体的 `cDir`。
  原有的 `facing`（±1）仍在，模拟自己还在用。
- `World.fx / fxN` 是特效事件队列，**渲染层每帧消费后必须把 `fxN` 清零**，否则会溢出。
- `atkAnim` 在出手那一刻被设为 0.3 再按秒递减，所以攻击动画是「命中之后」播放的 0.3 秒：
  动作要设计成一开始就快速出手、后面慢慢收势，否则伤害跳出来时手还没挥。
- `anim` 每移动 1 像素加 0.11。跑步循环的相位 = `anim × 系数`，系数决定脚下打不打滑：
  步兵 0.32（一个循环约 3 米），骑兵等大单位 0.26。改步幅或单位速度时要一起改。
- 桥：模拟里是可通行的 `T_BRIDGE` 格，渲染里那一格的地形是河床，`groundY` 对桥格直接返回桥面高度。

## 渲染上踩过的坑

- **上千单位怎么画**：每个兵种把所有动画帧的骨骼矩阵烘进一张浮点贴图（一行一帧，一根骨骼 4 个纹素），
  几何体带骨骼编号，实例属性只给「位置 + 朝向 + 第几行」。不要逐个单位做蒙皮，也不要每单位一个 Mesh。
- **性能是这样调回来的**：约 2000 单位同屏时最初只有 38 FPS，三项改动后回到 60：
  几何体合并顶点改成索引绘制；每顶点骨骼数从 4 降到 2；镜头拉远（距离 > 2400）时单位不再投影。
  人物用不封口的圆管做肢体省面。马是面数大户（约 2200 面，骑兵合计近 3000 面），再要提速先从马下手。
- **`Puppet.pose` 复位时必须跳过根节点**。早先连根节点一起复位，调用方给模型设的缩放和朝向被清掉，
  表现为「马缩成一小团」「模型朝向不对」，很难联想到是这里。
- **马的模型**：glTF 里骨架和网格节点各带一个 100 倍缩放，直接读包围盒不可信，
  要用 `skinnedBox`（按骨骼矩阵算）来量再缩放。动画有带 `AnimalArmature|` 前缀的重复项，取不带前缀的。
- **骑手的座位**：取马的 `Torso` 与 `Torso3` 两根骨骼之间 0.6 处，每帧跟随。只取 `Torso` 会坐到马屁股上。
- **贴地标记（选中圈、占领圈）**：要画在地形之上、单位之下。做法是材质 `transparent: false` + 自定义混合，
  让它留在不透明队列里，再用 `renderOrder` 紧跟地形绘制并关掉深度测试。
  放进透明队列的话会在所有单位之后才画，圈就盖到人身上了。
- **战争迷雾**：不是后处理，是一张小贴图（64 像素一格）在每个材质的片元着色器末尾压暗。
  新增材质要走 `materials.ts` 的 `litMaterial`，否则迷雾里它会是亮的。
  未探索区域只压暗、不抹黑：地形是已知的，看不到的是敌军和建筑。
- **建筑**：按「模型种类」分组成 `InstancedMesh`，只有当某栋建筑的存活 / 归属 / 血量档 / 受击闪白 / 是否已探索
  变化时才重写实例缓冲（`syncBuildings` 里的签名比较）。归属色只体现在旗帜上，建筑本体不随归属换色。
- **头像**：`portrait.ts` 用一个独立的离屏渲染器现渲，必须在素材（马）加载完之后才能调用，
  所以 `main.ts` 先 `loadAssets()` 再进菜单。
- three.js 固定在 0.170；着色器补丁依赖它的 `#include <begin_vertex>` 等片段名，升级后要重新核对。

## 调试手段

- 直达参数：`/?f=china&e=japan&size=600&seed=42&fog=0&spectate=1`。开发模式下 `window.game` 是当前对局
  （`game.world`、`game.renderer.cam`、`game.renderer.three.info.render` 等都能直接读写）。
- 模型预览页：`/?view=units`，`&k=legion` 只看一个兵种，`&clip=move` 固定播放某个动作；`window.viewer` 里有相机和控制器。
  调模型、动作先在这里看，比进对局快得多。
- 想马上看到大规模交战：在控制台把两军的坐标搬到同一处、各下一道攻击移动、再把 AI 的 `update` 换成空函数。
  注意开打后减员很快，测帧率要在头十几秒内取数。
- 量帧率用 `requestAnimationFrame` 数 3–4 秒的帧数，不要看界面左上角那个平滑过的读数。

## 已验证与未验证（截至首个里程碑）

已在浏览器里实测：镜头平移 / 缩放；框选、右键移动、攻击移动、编队、小地图点击跳转；战争迷雾；据点占领；
约 1800–2060 单位同屏混战 60 FPS（窗口 1625×913，被刷新率封顶）。`npm test` 10 项通过，`npm run build` 通过。

没有验证过：

- 右键指定攻击敌军或建筑、R 设集结点、小地图右键下令、Q/E 与 Alt + 中键旋转镜头的真实输入
  （镜头旋转只通过直接改参数看过）。
- 援军入场与胜负结算在 3D 下的表现（逻辑没改，但没等到实际触发）。
- 2600 单位全部同屏时的帧率；非 Apple 芯片或集成显卡上的表现。
- 成队行军时脚下是否还打滑；完整的一局人机对战。

## 已知的遗留

- 没有音效。
- 桥不可破坏，也没有栏杆（桥常是斜着跨河，栏杆方向会错）。
- 大部队绕河找渡口时会沿岸拉成长队。
- 单位在坡上不会随坡度倾斜；下摆、披风、旗帜是刚性的，不会飘动。
- 披甲的马只是把躯干换成甲色，没有单独的马甲模型。
