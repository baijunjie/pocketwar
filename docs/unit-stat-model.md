# 兵种数值建模的依据与待定事项

点数机制本身（怎么配兵种、阵营）见 `docs/product/units.md`「点数机制」；本文留的是机制背后的实测依据、设计取舍，以及还没做的事。动价目表、点数口径、伤害公式、兵力占用之前先读。

## 设计取舍

### 伤害公式

- 伤害 = d × d ÷（d + 2 × 护甲 ×（1 − 破甲）），d = 攻击 × 克制倍率（打建筑再乘对建筑倍率），单位与建筑同一条公式，不设保底。
- 不照搬帝国时代 2 的减法（「攻击 − 护甲」、保底 1）：减法会出现打不动的情况，帝国时代 2 靠玩家现造克制兵种化解；本游戏阵营编制固定，打不动就成了解不开的对阵劣势。
- 不用纯比例减伤：重击与快击会完全等价，「重击穿甲」这条兵种差异没了。
- 换公式时四阵营之间的强弱几乎不变，原有护甲数值沿用。

### 经验值与兵种强弱脱钩

- 被击杀给出的经验值只看原型（高级形态按统一倍率）。原先经验值 = 战力估值 × 10，兵种越强给对手的经验越多，而升一级攻防各 ×1.5，在升级线附近造成跳变：
  实测骑兵生命 +8 级本该值 +0.11–0.13，实际只有 +0.047，输出 +8 级甚至变成负值。脱钩后兵种价值才平滑、可度量。
- 战力估值（士气与电脑用）仍随兵种强弱变，它的影响是平滑的（约为生命价值的一到两成）。

### 维度

- 攻击不拆成「攻击」「攻速」，而拆成「输出」（只改间隔）与「节奏」（单次伤害与间隔同乘）：连弩（6 / 0.6 秒）与铁炮（46 / 4.8 秒）每秒伤害几乎相同，差的只是节奏。
- 维度可以降到基准以下，否则做不出「玻璃大炮」和「步兵单薄」。等级与高级形态对所有兵种是同一套倍率，不计点。

### 器械拆成抛射与直射两个原型

- 原先只有一个「远程器械」原型，基准取现有器械的中位数，带范围杀伤（半径 30）。平地对冲里范围杀伤对器械值约 6.7 点（范围杀伤 −15 级计 −6.68 点），
  直射追踪、没有范围杀伤的重弩（蝎弩）按负级数去掉它，生命、输出、破甲加满也只有约 −4 点，破单兵种下限；
  反过来把范围杀伤改成加价特性，抛射的器械又会各多 6.7 点冲破上限。两者是不同的武器体系，所以拆成两个原型，各有基准（基准 = 0 点），
  每人价值的差别交给兵力占用。代码里范围杀伤大于 0 的投射物飞向预判落点，等于 0 的追踪目标，所以直射器械不开范围杀伤维度。
- 直射器械的基准取它唯一的兵种蝎弩迁到原型之前的重弩面板（生命 100、单发 90、间隔 4.5 秒、射程 400、机动 42、最近射程 60），
  伤害类型取远程缺省的穿刺（直射器械的兵种都是穿刺，不另作特性）；破甲与其它原型一样基准为 0，由兵种按级数加（蝎弩 +8，即 80%）；
  「重弩」（克制载具 ×2）仍是特性。开放的维度与抛射器械相同，去掉范围杀伤。
- 标准混编军的人数构成不变：直射器械的位置不进标准混编军，顶替器械位（`POSITIONS` 的 `ref`），
  它的价目与兵种实测在「器械位整个换成直射器械基准」的军队上量，参照组也是这支军队，斜率仍用标准混编军的。阵营点数里它的份数之比按器械位的人数比例算。
  以后同一位置再出现武器体系不同、要按负级数去掉基准属性才配得出来的兵种，照这个做法拆原型。

### 兵力占用

- 兵力按占用计，不按人头：实测日本的兵种并不弱，弱在编制里没有战象与骑射、器械很少，而这些原型每人的价值是步兵的几倍到十几倍；按人头计，缺高价值原型的阵营天然吃亏。
- 占用值取每人价值的比值（相对枪兵基准约为：步兵 1.9、远程 0.65、骑兵 2.9、骑射 2.2、器械 5.5、战象 14.5），落到现值后以 `npm run measure -- force` 核对。
- 直射器械的占用取 1。2026-11-25 按同一规程核对（标准混编军 300 人，器械位换成直射器械基准后加 3 人）：−0.35 ±0.26 点，不显著，取有依据的初值：
  同一批种子里「器械位整个换成直射器械基准」比标准混编军少 3.3 点（显著），即每个直射器械比抛射器械少值约 0.37 点，
  每人约 0.076 点，相对近战步兵（每人 0.098）约 0.8，相对抛射器械（每人 0.44，现用占用 6.4）折算约 1.1，取整齐数 1。
  重弩在平地对冲里不值钱：约三成弩箭在飞行途中目标已死而落空，射速又被走位拖累；抛射器械的价值几乎全在范围杀伤（把它的伤害清零后同样大败）。

### 阵营预算

- 目的是做好点数机制与算法，不追求现有阵营的绝对平衡；阵营将扩展到十几个，两两循环赛调平的成本随阵营数平方增长，也做不到绝对平衡。
- 「各阵营点数相同」落成配置规则：每个阵营的阵营点数不超过同一个预算，按价目表计账，配完即得、不跑对战，随阵营数线性扩展。
- 兵员与援军数量是阵营级维度（兵员级数、援军级数，每级人数 ×1.035，可取小数、可为负），多兵就得少质量，都计入点数：保留「兵多 / 兵精」的特色又不游离在预算之外。
- 预算取现有四阵营在迁移前兵员级数（阵营特色倍率换算：中国 1.69、日本 −2.11、罗马 −1.95、波斯 −1.19）下阵营点数的中位数，差额用兵员级数补齐。编制比重由阵营自定，兵种数量与原型覆盖不作统一要求。
- 阵营测量与平地循环赛保留为参考工具，不作门槛：克制关系带来的相性很强，单一的强度数字预测不了两两对阵（原型阶段 100 人规模下，波斯对标准混编军 +0.29，对日本只是平手，对罗马大败 −0.41）。

## 点数的标尺与实测依据

以下是原型阶段（平地对冲，关掉昼夜天气与迷雾，双方相距 1400，攻击移动到中点，最长 420 秒）的实测，数字随规则变化会漂移，要新数字用测量工具重量。

- **战果**：双方剩余生命占开局的比例之差（「优势」）；同一对阵换边各打一场取平均算一个样本。单个样本标准差 0.07–0.10，48 个样本标准误约 0.01，折合约 0.2 点。
- **标准混编军**：现有四阵营开局编制的平均，各位置人数占比为近战步兵 26%、长柄 22%、远程 31%、近战骑兵 12%、远程骑兵 5%、器械 3%（抛射器械基准）、载具 1%（`tools/measure/units.ts` 的 `REF_SHARE`，只在校准时显式更新）。直射器械的位置顶替器械位，见「器械拆成抛射与直射两个原型」。
- **标尺**：对手是标准混编军，己方全军生命加减若干级：

  | 级数 | −12 | −8 | −4 | −2 | 0 | +2 | +4 | +8 | +12 |
  |---|---|---|---|---|---|---|---|---|---|
  | 优势 | −0.51 | −0.35 | −0.23 | −0.17 | +0.01 | +0.15 | +0.24 | +0.42 | +0.59 |

  离开势均力敌之后是线性的，每级约 0.045–0.055；势均力敌附近很陡（±2 级就到 ±0.15），因为胜负一旦分出赢家总会剩下两成多。
  所以量小差异时让一方先让 6 级生命（`HANDICAP`），落在线性段里，再用同一批种子量出的 ±3 级斜率（`SLOPE_LEVELS`）换算成点数。
- **点数的含义**：兵种点数 = 把标准混编军里它对应的位置整个换成它之后，全军相当于生命加了几级，由对战量出来，包含全部特性的真实效果。
- **线性段里基本可加**：各原型各自生命 +8 级的效果之和等于全军生命 +8 级的效果；经验值脱钩后，各原型之和比全军一起加高约两成，即单独强化一个原型的收益略高于全军一起强化。全军输出 +8 级约为全军生命 +8 级的 0.75 倍。
- **为什么价目分原型实测，不用「有效生命 × 有效输出」的公式**：
  - 生命的价值取决于它占全军生命池的比例（步兵 30% 对 29%，骑兵 27% 对 22%）。
  - 输出的价值取决于实际打出去的伤害，不等于面板每秒伤害：器械与战象靠范围杀伤，价值是名义输出的 5–7 倍；骑兵的普通攻击几乎没有价值，输出在冲锋上。
  - 远程兵种的远程护甲几乎无效（多死于冲锋、范围杀伤和溃逃）；射程比基准更远没用、更近有损失；机动在平地对冲里近乎无效。
- **直射器械的价目**（2026-11-25 量）：生命 +0.042 / −0.038、输出 +0.12 / −0.15 每级，重弩 +2.09；
  节奏 +4 级 −1.58、机动 +4 级 −2.49、射程 ±4 级各 −1.1 与 −1.3（都显著）：重弩加快、跑快、射远都变差，多半是脱离了阵型、更早被冲到，
  这些加级价目按规程记 0（战略维度取地板价），配点时以实测为准。护甲、纪律、破甲近乎 0。
  蝎弩（破甲 +8、重弩）估算 2.09、实测 0.59 ±0.26：重弩的价目是在不破甲的基准上量的，叠上破甲后不完全可加。
- **机动、射程、纪律**：平地会战里量不出价值（或价值很小），但整局里有用（抢据点、守城、断粮与夜战时的士气）。目前加级价目用不为零的地板价（同位置生命加级价目的 1/3），只按高于基准的级数计入兵种点数，低于基准不计、不退点。

## 估算与实测的边界

- 估算（价目表）用来在调数值时指路，实测（`npm run measure -- unit` / `units`）用来定论。两者相差超过 1 点的兵种用 `npm run measure -- report` 列出。
- 价目表按单维度可加计账，叠加极端的兵种估算偏差约 1 点（节奏 × 破甲、武士道 × 输出这类交互项没有单独定价）。
- 价目表里有很多格统计上不显著、记 0（当时 112 格里 52 格）：价目是在标准混编军上单个维度 ±8 级（或 ±4、+4/−3）量的，多个维度、特性叠在一起时不完全可加。
- 兵种与位置基准差得远时，估算照样失真：拆分前的远程器械价目是在带范围杀伤的基准上量的，没有范围杀伤的蝎弩估算 +3.51、实测 −4.28（因此拆出直射器械）；
  军团步兵、不死军、大筒、武士、铁甲骑兵也曾相差超过 1 点。配这类兵种以实测为准。
- 工具耗时（单核）：全部兵种量一遍约 13–17 分钟，价目表重量约 2 小时，要并行（`--workers`）。
- 测量指纹变了而已有格子的对战其实没变（例如新增原型、位置或改了名称）时，不必全部重量：先用 `npm run measure -- prices --check <标签…>` 抽测，
  再用 `prices --reuse` 沿用旧测量、只量新增的格子（2026-11-25 拆分器械时抽测 6 格逐位相同，只量了直射器械的 18 格；
  同日加光环特性时抽测 17 格逐位相同，只量了盾墙掩护的 2 格）。
  - 抽样规则（只看旧测量里标签还在这次清单上、要沿用的格子）：每个位置至少一格维度格，每个特性格都抽，兵员一格；每格整行逐位相同才算相同。
    同一位置的维度格共用位置基准单位，基准单位又在标准混编军（所有格子的参照组与斜率）里，它变了这些格都跟着变，抽一格就能发现；
    特性是各自的定义，只影响自己那一格，所以逐格抽。只改某一个维度的阶梯这类改动抽样发现不了：`--reuse` 只用于不动已有定义的改动（新增原型、位置、特性、规则项，改名称），其余照常全部重量。
    改了结算代码的，只有在对现有单位逐位不变（如乘以无加成值 1，Float32 的 1.0 不改变结果）、且不多调用 `w.rng` 时才算不动已有定义：多一次随机数调用，所有对战的走向都会变。
  - 抽测通过才写通过记录（`tools/measure/out/price-check-pass.json`，含当前测量指纹、旧测量的摘要与抽测结果）；`--reuse` 只认与当前测量指纹、
    当前旧测量都对得上的记录，否则报错要求先 `--check`。不经核对就沿用，过期测量会被写上新指纹、指纹过期的测试也跟着通过。
    记录不进版本库：它只证明本机这份旧测量在当前定义下抽测相同，`--reuse` 写回测量文件后就自然作废。
- 价目的指纹分两份，都不含具体兵种（配新兵种不会让它们过期）：测量指纹记在 `price-measurements.json`，含规则、原型、特性、位置与测量规程（对战规程、各测量的规模与样本数、种子、测价的级数、兵员测几级）；汇总指纹记在 `prices.json`，在测量指纹之上再含地板价规则。汇总规则本身由测试直接核对「按提交的测量重新汇总等于提交的价目表」。
- 阵营点数相等不等于对战平手：克制与编制带来的对阵相性很强，兵员价格也只是近似；阵营强弱的实战检验放在整局对战。
- 实测的点数在差额很小时不显著，误差约 ±0.3 点；同一组种子的结果是确定的（基准单位本身量出来正好是 0）。
- 兵种实测表与价目都带指纹，规则、原型、特性、位置或测量规程变了就过期（兵种实测表另含兵种定义与价目表）；系统代码本身（结算算法）不在指纹里，改了结算算法要自己想到重量。

## 其它实现上的约定

- 援军取整：一批援军只有十几个人，每个兵种按份数四舍五入且至少 1 人，援军级数在 ±3 级内常常不改变任何兵种的人数，级数的效果主要体现在城池与城镇累计出兵上的取整边界，不是每批都变。
  价目表、兵种、编制、援军表或阵营增减之后，用 `npm run measure -- budget --write` 与 `npm run measure -- reinf --write` 重算两个预算与各阵营的兵员级数、援军级数。
- 体型上的口粮份数是另一套数值，管粮草消耗与高级形态的升级花费，不要和兵力占用混用。
- 位置基准带某个属性（例如抛射器械带范围杀伤）时，该属性的基准值就是它，没有的兵种按负级数计；不要改标准混编军的人数构成。
  负级数大到兵种配不进上下限、又属于另一种武器体系的，拆出新原型并让它的位置顶替原位置（见「器械拆成抛射与直射两个原型」）。

## 待定与未做

- **维度之间的交互**：要不要补交互项，或改为联合测价，待定（现状见上，偏差约 1 点）。
- **建筑的护甲、生命与攻击机制是否整体重做**：伤害公式已统一，但这三样本身要不要重新设计尚未讨论；对建筑倍率、最近射程这类只影响攻城的属性怎么计点也待定，现在照原值保留、不计点。
- **神职与载具行为**：神职的治疗规则、载具里战车与冲车的行为尚未设计，神职原型未落地。点数里的治疗维度（每级治疗量 ×1.05）已声明、未启用，等神职落地、兵种表有了治疗量字段后补上量价。
- **渲染侧「骨架与动画归原型、各文明只换外观」**：载具与器械下各兵种的骨架并不相同，渲染侧的模型与动画还没有按原型归并。
- **平地会战之外的情境**：实测只在平地对冲里做，攻城、守城、地形与天气下各维度值多少没有量过，没有兜底。
- **机动、射程、纪律的整局定价**：原想用整局镜像对局（每个阵营每个维度各 40 局）定价；整局胜率混着电脑的指挥水平、局数多且精度低，所以先用地板价，要不要做、怎么做待定。
- **兵力占用的现值与核对结果相差较大**：2026-11-25 的 `force` 核对（相对近战步兵）为远程步兵 0.82、近战骑兵 3.33、远程骑兵 3.67、抛射器械 4.49、载具 3.27，
  现用 0.76、3.75、1.5、6.4、6.3；远程骑兵、抛射器械、载具都显著且相差超过两成。要不要按核对结果改、改了以后预算与编制怎么跟着换算，待定。
- **战略维度的整局定价**与上一条同源：战略维度（机动、射程、纪律高于基准的级数）目前按地板价计入兵种点数，再随兵种点数进阵营点数。
- **光环特性挂到哪些兵种、数值多少**：「盾墙掩护」（所受远程伤害 −20%、半径 60）已定义并在近战步兵与长柄两个位置计价，还没有兵种带它；
  挂到哪些持盾步兵（刀盾兵、军团步兵、辅助矛兵、持盾矛兵这类）、半径与倍率取多少属于阵营配点，待定。挂上后按价目表计点，用 `budget --write`、`reinf --write` 重算预算与级数；
  不再需要的计价位置从特性的 `priceAt` 里删掉。光环价值是在标准混编军的阵型与构成下测的，远程兵比例更高的阵营里实际价值会偏高，属于价目表按单项可加计账的既有边界。
  另外两件也待定：选中单位时要不要在地上画出光环范围（现在只在兵种提示里显示）；更多加成种类（士气、攻击间隔、移动速度等）按同一机制往加成种类里加，各自另行设计。
