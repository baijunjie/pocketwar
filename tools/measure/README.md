# tools/measure：对战测量工具

开发工具，不属于游戏本体：游戏运行时（`src/`）不引用本目录，反过来本目录读 `src/sim/` 的内容表并复用模拟层无头跑对战。

做什么：让「被测的一方」与标准混编军在平地上无头对战，把优势换算成点数（1 点 = 标准混编军全军生命加 1 级），用来量出各原型、各位置的价目表、兵种的实测点数，并核对阵营点数与预算。
顶替别的位置的位置（`POSITIONS` 的 `ref`，现在只有直射器械顶替器械位）不进标准混编军：量它时把被顶替的位置整个换成它的基准单位，参照组也是这支军队，
标准混编军的人数构成与已有各格价目因此不受影响。点数机制与阵营预算的规则见 [`docs/product/units.md`](../../docs/product/units.md)「点数机制」与 [`docs/product/factions.md`](../../docs/product/factions.md)，实测依据见 [`docs/unit-stat-model.md`](../../docs/unit-stat-model.md)；估算用的点数代码在 [`src/sim/content/points.ts`](../../src/sim/content/points.ts)。

## 文件

| 文件 | 职责 |
|------|------|
| `cli.ts` | 命令行入口，全部命令与选项的用法写在文件头 |
| `measure.ts` | `Measurer`：标尺、维度、人数、兵种、阵营、循环赛等测量，并把优势折算成点数 |
| `battle.ts` | 测量规程里的一场对战（平地、双方相距、残部重新寻敌、胜负已分就收兵） |
| `army.ts` | 军队描述（可序列化的纯数据）与建军：标准混编军按位置混编，位置可加级数或人数 |
| `units.ts` | 各位置的基准单位、标准混编军的构成与兵力折算、顶替位置的参照组、按级数造变体兵种 |
| `job.ts` | 一个对阵（纯数据）与在本进程里跑它 |
| `runner.ts`、`worker.ts` | 把一批对阵按种子切开分给多个工作进程并行跑，缺省进程数取本机性能核数；工作进程跑 esbuild 打包后的 `worker.ts`（比 vite-node 直接跑源码快约一倍，结果逐位相同）；结果与进程数无关 |
| `stats.ts`、`table.ts` | 样本统计（配对差、显著性、序贯检验的停止规则）；结果输出为终端表格与 TSV |
| `price.ts` | 价目表的量法（每个位置、维度、特性一格；特性格见下「测价清单」）与由测量行推出价目 |
| `unitpoints.ts` | 兵种实测表的读写，以及与估算点数的偏差核对 |
| `faction.ts` | 阵营点数与援军点数的计账：兵种点数 × 份数之比 + 战略维度成本 + 兵员（援军）成本，及补到预算要的级数 |
| `reuse.ts` | 沿用旧价目测量的核对：抽测的逐位比较、抽样规则、通过记录与 `--reuse` 的放行判断（纯函数） |
| `fingerprint.ts` | 把影响对战的兵种定义、规则与规程摘成指纹，存进生成物；对不上说明结果已过期 |
| `node-shim.d.ts` | 本工具用到的 Node 接口的最小类型声明 |

## 测价清单

特性按「位置 × 特性」一格计价：位置基准全员挂上该特性实测。要计价的格子是两部分的并集（位置基准本来就带的特性不计）：

- 有兵种带它的位置（兵种自有特性，`positionTraits()` 给出位置基准本来就带的、不另计价的那部分）；
- 特性自己声明的 `TraitDef.priceAt`：先定义、还没挂到兵种上的特性（如光环特性 `cover`）靠它先有价目。挂到兵种后不再需要的位置要手动从 `priceAt` 删掉，否则每次重量都多量这几格。

光环特性与其它特性同一套规程，光环参数与光环更新间隔随特性与规则进测量指纹。

## 命令

项目根目录运行 `npm run measure -- [选项] <命令> [参数…]`（以 `vite-node --script` 运行 `cli.ts`，被导入时不执行），选项有 `--workers`、`--size`、`--n`、`--out`。

测量规程：每场打到一方死光、胜负已分（败方作战生命 ≤ 5% 且胜方是它的 4 倍以上）或 420 秒；换算点数的测量（维度、特性、人数、兵员、兵种、阵营）按序贯检验每批 16 组，明确显著或明确不显著就停，`--n` 与缺省样本数是上限，行里的 `n` 是实际组数、`stop` 是停止原因。规程的依据与取舍见 [`docs/unit-stat-model.md`](../../docs/unit-stat-model.md)。

| 命令 | 作用 |
|------|------|
| `base`、`ladder`、`dim`、`count`、`countslots`、`force` | 基准面板、标尺、维度、人数、兵力占用的测量 |
| `unit`、`uvar` | 兵种整体测量；在兵种上再加减级数的试算 |
| `faction`、`roundrobin`、`fmod`、`pair` | 阵营测量、循环赛与试算（参考用，不作门槛） |
| `breakdown`、`reinf` | 阵营点数与援军点数明细（不跑对战）；`reinf --write` 重算援军预算与各阵营援军级数并写回 `points.ts`、`factions.ts` |
| `prices`、`manpower`、`units` | 重量价目表、兵员每级价格、全部兵种的实测点数（生成物见下） |
| `prices --check`、`prices --reuse` | 测量指纹变了而已有格子的对战没变时：`--check` 重量抽样格子与旧测量逐位比较，每格相同且抽样覆盖了要沿用的格子（每个位置一格维度格、每个特性格、兵员一格），才写通过记录；`--reuse` 只在通过记录与当前测量指纹、当前旧测量都对得上时放行，沿用旧测量、只量新增的格子，否则报错要求先 `--check` |
| `report` | 对照兵种实测表与估算点数，列出偏差超过 1 点的兵种 |

## 生成物（不手改）

| 文件 | 由谁生成 |
|------|----------|
| `data/price-measurements.json` | `prices`、`manpower`：价目表的原始测量行 |
| `data/unit-points.json` | `units`：兵种实测表 |
| [`src/sim/content/prices.json`](../../src/sim/content/prices.json) | `prices`、`manpower`：由测量行推出的价目表，游戏代码的估算读它 |
| `out/` | `prices` 的中断记录、`prices --check` 的通过记录 `price-check-pass.json` 等中间产物，不进版本库 |

生成物里存着指纹，兵种定义或规则变了而没重新生成时，`tests/` 里对应的测试会失败。
